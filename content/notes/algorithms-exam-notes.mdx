<Fold title="words that show up in every lecture">

- **n** is the size of the input. **k** is a rank you are asking for. **log** is base 2 unless a base is written.
- **rank**: the position of an element in sorted order. The smallest element has rank 1, the largest has rank n. "The kth smallest" and "the element of rank k" mean the same thing.
- **comparison**: asking "is a &lt; b?" and getting yes or no. Most algorithms in lectures 4 to 8 are counted by how many comparisons they make.
- **worst case**: T(n) is the most work over <U>all</U> inputs of size n. It is a function of n, not of one input.
- **recurrence**: an equation for T(n) in terms of T of smaller inputs, like T(n) = 2T(n/2) + cn. Read it as: "two recursive calls on half the input, plus cn work of my own".
- **O, Ω, Θ**: upper bound, lower bound, both (lecture 2, at the bottom).
- **invariant**: a statement that is true at the start of every step of an algorithm. You prove it by induction over the steps.
- **potential Φ**: a number computed from the current state of a data structure, used to pay for expensive steps (lecture 7).

</Fold>

**What the course is.** There is no programming. You design an algorithm and then prove two things about it: it is **correct** (its output is what you claim), and it is **fast** (at most f(n) steps on every input of size n).

<Fold title="why prove a running time instead of timing it? (3 reasons from lecture)">

- Test inputs may not look like real inputs, and a low-level routine meets every kind of input.
- We care how the time **scales** with n. That is hard to read off experiments.
- A proof makes you understand **why**. An experiment only tells you that it happened.

</Fold>

### three ways to multiply

- **From the definition:** add X to itself Y times. Y can be as large as 2ⁿ, so that is Θ(2ⁿ) additions.
- **Grade school:** for each 1 bit of Y, write down a shifted copy of X, then add the copies up. There are at most n copies and each addition costs O(n): <O>O(n²)</O>.
- **Karatsuba (1962):** O(n<sup>1.585</sup>). The obvious algorithm was not the best one.

### Karatsuba

<Steps title="Karatsuba, from 4 products to 3">

<Step>

Split each number in half: X = 2<sup>n/2</sup>·A + B and Y = 2<sup>n/2</sup>·C + D. A and C are the top n/2 bits, B and D are the bottom n/2 bits.

</Step>

<Step>

Multiply out: XY = 2<sup>n</sup>·AC + 2<sup>n/2</sup>·(AD + BC) + BD. That needs four half-size products (AC, AD, BC, BD). The shifts and additions cost O(n).

</Step>

<Step>

So T(n) = 4T(n/2) + cn, which solves to O(n²). No progress yet.

</Step>

<Step>

The trick: (A + B)(C + D) = AC + AD + BC + BD. So the middle term is <Hl>AD + BC = (A + B)(C + D) − AC − BD</Hl>. We need AC and BD anyway, so one more product gives the middle term.

</Step>

<Step>

Three products: AC, BD and (A + B)(C + D). T(n) = 3T(n/2) + cn = <O>O(n<sup>log₂ 3</sup>)</O> ≈ O(n<sup>1.585</sup>). The c is larger than before, but it is still a constant.

</Step>

</Steps>

Lecture writes the same identity in one line: XY = 2<sup>n/2</sup>(A + B)(C + D) + (2<sup>n</sup> − 2<sup>n/2</sup>)AC + (1 − 2<sup>n/2</sup>)BD.

**By hand.** 54 × 41 as 6-bit numbers: X = 110110 and Y = 101001, so n/2 = 3.

- A = 110 = 6, B = 110 = 6, C = 101 = 5, D = 001 = 1
- AC = 30, BD = 6, (A + B)(C + D) = 12 · 6 = 72
- middle = 72 − 30 − 6 = 36 (check: AD + BC = 6 + 30 = 36 ✓)

### O, Ω, Θ, o, ω

All five compare two functions as n grows. In lecture's letters, g is the function you have and f is the yardstick.

- **g = O(f)**, an upper bound: there are constants c, n₀ &gt; 0 with g(n) ≤ c·f(n) for all n &gt; n₀.
- **g = Ω(f)**, a lower bound: the same with g(n) ≥ c·f(n).
- **g = Θ(f)**, tight: both of the above. The two proofs may use different constants.
- **g = o(f)**, strictly smaller: for <U>every</U> c &gt; 0 there is an n₀ with g(n) &lt; c·f(n) for all n &gt; n₀. The ratio g/f goes to 0.
- **g = ω(f)**, strictly bigger: for every c, g(n) &gt; c·f(n) from some n₀ on. The ratio goes to ∞.

<Margin>O(f) is really a set, so "g ∈ O(f)". everyone writes g = O(f).</Margin>

This is notation for functions, not only for running times. It also bounds space, or anything else that grows.

<Fold title="the lecture's examples, with their constants">

- 2n² + 27 = O(n²): n₀ = 6, c = 3
- 2n² + 27 = O(n³): n₀ = 4, c = 1 (an upper bound does not have to be tight)
- n³ + 2000n² + 2000n = O(n³): n₀ = 10000, c = 2
- 2n² + 27 = Ω(n²) and Ω(n): n₀ = 1, c = 1
- n³/100 − 1000n² = Ω(n³): n₀ = 1000000, c = 1/1000
- 2n² + 27 = o(n² log n) and ω(n)

</Fold>

<Steps title="proof that 2n² + 27 = O(n²)">

<Step>

We have to name a c and an n₀. Try c = 3.

</Step>

<Step>

When does the bound fail? 2n² + 27 &gt; 3n² means n² &lt; 27, so n &lt; 6.

</Step>

<Step>

So 2n² + 27 ≤ 3n² for every n ≥ 6.

</Step>

<Step>

Take n₀ = 6. For all n &gt; n₀ we have 2n² + 27 ≤ c·n². That is the definition, so we are done.

</Step>

</Steps>

### recurrences

A **recurrence** writes T(n) as the cost of the recursive calls plus the work the call does itself.

- selection sort: T(n) = T(n − 1) + cn (find the smallest in cn, then recurse on the rest)
- mergesort: T(n) = 2T(n/2) + cn (two halves, then a merge that costs cn)
- the base case is T(n) ≤ c for n below some constant. It is almost always obvious and usually left out.

There are three ways to solve one.

**1. Unrolling** (good when there is one recursive call). T(n) = T(n − 1) + cn = cn + c(n − 1) + … + c. There are n terms, each at most cn, so O(n²). At least n/2 of the terms are at least cn/2, so Ω(n²). Together <O>Θ(n²)</O>.

**2. Guess and check** (induction).

<Steps title="guess and check on T(n) = 3T(n/3) + n, T(1) = 1">

<Step>

Guess T(n) ≤ cn, and assume it for all smaller inputs.

</Step>

<Step>

Then T(n) = 3T(n/3) + n ≤ 3·c(n/3) + n = (c + 1)n.

</Step>

<Step>

That is <X>not</X> a proof of O(n). We needed ≤ cn and got (c + 1)n. The constant grew, so <Hl tone="pink">it was never a constant</Hl>.

</Step>

<Step>

A better guess: the "constant" went up by 1 each time n tripled. The function that does that is log₃ n. Guess T(n) ≤ n log₃(3n). The 3 inside makes the base case work: T(1) = 1 ≤ 1·log₃ 3.

</Step>

<Step>

Check: T(n) ≤ 3·(n/3)·log₃(n) + n = n log₃ n + n = n(log₃ n + log₃ 3) = n log₃(3n) ✓. Exactly the bound we assumed, so T(n) = O(n log n).

</Step>

</Steps>

<Check q="An induction assumes T(m) ≤ 5m for smaller m and derives T(n) ≤ 6n. Is T(n) = O(n) proven?" options={["no: the constant changed, so the induction did not close", "yes, 6n is O(n)", "yes, if n is large enough", "only the base case is missing"]} why="You must derive exactly the bound you assumed, with the same constant. Otherwise the constant grows at every level of the recursion." />

**3. The recursion tree** (the one lecture always uses). Draw one box per call, holding only the work that call does itself. Add up each level, then ask which level is biggest.

- mergesort: level i has 2<sup>i−1</sup> boxes of c·n/2<sup>i−1</sup> each. Every level adds up to cn, and there are log n + 1 levels: <O>Θ(n log n)</O>.
- Strassen: level i has 7<sup>i−1</sup> boxes of c(n/2<sup>i−1</sup>)² each, a total of (7/4)<sup>i−1</sup>·cn². It grows every level, so the last level dominates: O(n²·(7/4)<sup>log n</sup>) = O(n<sup>log₂ 7</sup>).

### the master theorem

**Theorem 2.3.1.** For T(n) = aT(n/b) + cn<sup>k</sup> with T(1) = c, where a ≥ 1, b &gt; 1, c &gt; 0 and k ≥ 0 are constants:

- a &lt; b<sup>k</sup>: T(n) = Θ(n<sup>k</sup>). The top level dominates.
- a = b<sup>k</sup>: T(n) = Θ(n<sup>k</sup> log n). Every level is equal.
- a &gt; b<sup>k</sup>: T(n) = Θ(n<sup>log_b a</sup>). The bottom level dominates.

<Steps title="why: the recursion tree again">

<Step>

Level i has a<sup>i−1</sup> boxes of c(n/b<sup>i−1</sup>)<sup>k</sup> each. Its total is cn<sup>k</sup>·(a/b<sup>k</sup>)<sup>i−1</sup>.

</Step>

<Step>

There are log<sub>b</sub> n + 1 levels. Write α = a/b<sup>k</sup>. Then T(n) = cn<sup>k</sup>·(1 + α + α² + … + α<sup>log_b n</sup>).

</Step>

<Step>

**α = 1:** every term is 1 and there are log<sub>b</sub> n + 1 of them. T(n) = Θ(n<sup>k</sup> log n).

</Step>

<Step>

**α &lt; 1:** the sum is at least 1 and below 1/(1 − α), which is a constant. T(n) = Θ(n<sup>k</sup>).

</Step>

<Step>

**α &gt; 1:** pull out the last term. The sum is at most α<sup>log_b n</sup>·1/(1 − 1/α). So T(n) = Θ(n<sup>k</sup>·α<sup>log_b n</sup>) = Θ(a<sup>log_b n</sup>) = Θ(n<sup>log_b a</sup>).

</Step>

</Steps>

There exist constants c, n₀ &gt; 0 such that g(n) ≤ c·f(n) for all n &gt; n₀. For Ω, the inequality is g(n) ≥ c·f(n). For o, the inequality g(n) &lt; c·f(n) must hold for every c &gt; 0 (each c gets its own n₀), not just for one.

</Recall>

<Recall q="Master theorem: solve T(n) = 2T(n/2) + n, T(n) = 4T(n/2) + n and T(n) = T(n/2) + n.">

First: a = b<sup>k</sup> (2 = 2), so Θ(n log n). Second: a = 4 &gt; 2, so Θ(n²). Third: a = 1 &lt; 2, so Θ(n). The last one is quickselect with a perfect pivot (lecture 4).

</Recall>

<Recall q="In guess-and-check, why is deriving T(n) ≤ (c + 1)n from T(n/3) ≤ c·n/3 not a proof of O(n)?">

The induction must give back the same bound it assumed. A constant that grows by 1 at every level of the recursion has grown by log₃ n at the top, so the real bound is n log n.

Five proof shapes. The first three are shown on quicksort, the last two on insertion sort.

**Quicksort**, the running example. Input: an array A of n distinct elements.

1. If n ≤ 1, return A.
2. Pick some element p of A as the pivot.
3. Let L be the elements less than p, and G the elements greater than p.
4. Return Quicksort(L), then p, then Quicksort(G).

### 1. induction, weak and strong

- **weak:** prove a base case. Assume the claim for n = k, prove it for n = k + 1.
- **strong:** prove a base case. Assume the claim for <U>all</U> n ≤ k, prove it for n = k + 1.

<Steps title="quicksort is correct (strong induction on n)">

<Step>

**Claim:** Quicksort(A) returns the elements of A in sorted order.

</Step>

<Step>

**Base case**, n ≤ 1: it returns A, which is already sorted ✓.

</Step>

<Step>

**Hypothesis:** Quicksort is correct on every array of length ≤ n. Take any A of length n + 1.

</Step>

<Step>

It picks p and builds L and G. p is in neither, so both have length ≤ n.

</Step>

<Step>

By the hypothesis, Quicksort(L) and Quicksort(G) come back sorted. Call them L′ and G′.

</Step>

<Step>

</Step>

</Steps>

### 2. contradiction: the smallest counterexample

<Steps title="quicksort is correct (by contradiction)">

<Step>

Suppose some array is sorted incorrectly. Among all such arrays let A be a <Hl>smallest</Hl> one, of size n.

</Step>

<Step>

n ≥ 2, because arrays of size ≤ 1 are returned unchanged and are sorted.

</Step>

<Step>

Quicksort(A) picks p and recurses on L and G, which are both smaller than A.

</Step>

<Step>

A was the smallest failure, so L′ and G′ are sorted.

</Step>

<Step>

Then L′, p, G′ is sorted, so Quicksort(A) is correct after all. Contradiction.

</Step>

</Steps>

It is the strong induction proof turned inside out.

### 3. direct proof

Assume the hypothesis and derive the conclusion. Example: quicksort takes O(n²) time in the worst case.

- Before recursing it compares every element to the pivot: Θ(n).
- T(n) = T(|L|) + T(|G|) + Θ(n) = T(|L|) + T(n − 1 − |L|) + Θ(n).
- The worst case is a pivot that is the smallest or largest element: T(n) ≤ T(n − 1) + T(0) + Θ(n).
- Unroll T(n) = T(n − 1) + Θ(n) to get <O>Θ(n²)</O>.

### 4. loop invariant

**Insertion sort.**

```
for i = 2 to n:
    j = i
    while j > 1 and A[j] < A[j−1]:
        swap A[j] and A[j−1]
        j = j − 1
```

A **loop invariant** is a statement that is true at the start of every iteration. Proving one has three parts, and it is just induction on time:

- **initialization:** it is true before the first iteration
- **maintenance:** if it is true at the start of an iteration, it is true at the start of the next
- **termination:** when the loop ends, the invariant gives the correctness claim

<Steps title="insertion sort is correct (loop invariant)">

<Step>

**Invariant:** at the start of iteration i, A[1..i−1] holds the original first i − 1 elements, in sorted order.

</Step>

<Step>

**Initialization:** i = 2. A[1..1] is a single element, which is sorted ✓.

</Step>

<Step>

**Maintenance:** iteration i moves A[i] left until it is no longer smaller than its left neighbour. Now A[1..i] is sorted and holds the original first i elements. That is the invariant for i + 1 ✓.

</Step>

<Step>

**Termination:** the loop ends with i = n + 1. The invariant says A[1..n] is sorted and holds exactly the original elements ✓.

</Step>

</Steps>

<Guide fig="a loop invariant" shows="Insertion sort, one iteration of the outer loop per press. It marks the left part A[1..i−1], which the invariant says is sorted, and tells you whether the invariant holds.">
1. Press **next iteration** through insertion sort. At the start of each iteration the left part A[1..i−1] is sorted and holds the original first i−1 elements. That is the invariant.
2. Switch **code** to the bug ("stops before A[1]"). The invariant fails at a specific iteration, and the output is wrong.
</Guide>

### 5. contrapositive

"If P then Q" says the same thing as "if not Q then not P". Sometimes the second one is easier to prove.

Example, the maintenance step above. P: "x = A[i] is moved left until it is larger than the element to its left". Q: "at the end of the iteration, A[1..i] is sorted".

<Steps title="prove: not Q implies not P">

<Step>

Suppose A[1..i] is <U>not</U> sorted at the end of iteration i, and x ended up at position j.

</Step>

<Step>

Everything x moved past is larger than x: x &lt; A[k] for every k from j + 1 to i. So nothing is wrong to the right of x.

</Step>

<Step>

A[1..i−1] was sorted before the iteration, so the only way to be unsorted is some A[k] with k &lt; j and A[k] &gt; x.

</Step>

<Step>

The part left of x is still sorted, so A[j−1] ≥ A[k] &gt; x.

</Step>

<Step>

So x is still smaller than the element on its left. That is "not P" ✓.

</Step>

</Steps>

**Baseline:** sort A, then read position k. That is O(n log n). The question is whether O(n) is possible. It is, and that is the whole lecture.

**Warm-up cases** (lecture 4.1): k = 1 or k = n is one scan, keeping the smallest (or largest) so far. Any constant k, or n − constant, works the same way by keeping the k best. It fails for k = n/2: keeping the k smallest costs Θ(log k) = Θ(log n) per element, so n log n total. That is why the middle is the hard case.

<Fold title="words for this lecture">

- **pivot** p: one element of A that we compare everything else against.
- **L** and **G**: L is the set of elements smaller than p, G is the set of elements larger than p. |L| + |G| = n − 1, because p is in neither.
- **the key fact:** p has rank |L| + 1 in A. So comparing |L| to k − 1 tells you whether p is the answer, too big, or too small.
- **partition**: the one pass that compares every element to p and builds L and G. It costs n − 1 comparisons.
- **quickselect**: quicksort that only recurses on the one side that holds rank k.
- **median of medians**: a way to choose the pivot that is not the median but is never far from it.
- **BFPRT**: the name of the linear-time algorithm, from Blum, Floyd, Pratt, Rivest, Tarjan.

### quickselect, step by step

Call it Quickselect(A, k). Input and output are the same as selection.

1. If n = 1, return the element.
2. Pick a pivot p somehow.
3. Compare every element of A to p, building L and G.
4. Look at |L|:
   - if |L| = k − 1, then p has rank k: <O>return p</O>
   - if |L| &gt; k − 1, the answer is smaller than p: return Quickselect(L, k)
   - if |L| &lt; k − 1, the answer is larger than p: return Quickselect(G, <Hl>k − |L| − 1</Hl>)

The new rank in the last case is k − |L| − 1 because we just threw away |L| elements that are smaller than the answer, plus p itself, and every one of them was ahead of the answer in sorted order.

<Check q="k = 5, and after partitioning |L| = 6. Where is the answer?" options={["in L, still at rank 5", "in G, at rank 5", "it is the pivot", "in G, at a smaller rank"]} why="|L| = 6 is more than k − 1 = 4, so the pivot is too big. The 5th smallest is one of the 6 smaller elements, and its rank among them is still 5." />

**Why it is correct (invariant):** on every call Quickselect(X, a), the element we want from the original A is the a-th smallest of X. It is true at the start (X = A, a = k), and each of the three cases keeps it true.

**A trace by hand.** A = [9, 2, 7, 4, 8, 1, 6], k = 3, pivot = first element.

- p = 9. L = [2, 7, 4, 8, 1, 6], G = []. |L| = 6 &gt; 2, so recurse on L with k = 3.
- p = 2. L = [1], G = [7, 4, 8, 6]. |L| = 1 &lt; 2, so recurse on G with k = 3 − 1 − 1 = 1.
- p = 7. L = [4, 6], G = [8]. |L| = 2 &gt; 0, so recurse on L with k = 1.
- p = 4. L = [], G = [6]. |L| = 0 = k − 1, so return 4.

Check: sorted A is 1, 2, 4, 6, 7, 8, 9 and the 3rd smallest is 4 ✓.

### median of medians (BFPRT)

We want a pivot that is guaranteed to split the array reasonably, without knowing the true median (finding the median is the thing we are trying to do).

BFPRT(A, k) has the same input and output as selection.

1. If n ≤ 5, sort A and return its kth smallest.
2. Cut A into groups of 5 consecutive elements. Take the median of each group (sorting 5 elements is constant work). Put those n/5 medians into a new array A′.
3. Recursively find the median of A′: <Hl>p = BFPRT(A′, n/10)</Hl>. That is "the rank in the middle of n/5 elements".
4. Partition A around p into L and G.
5. Same three cases as quickselect: |L| = k − 1 return p, |L| &gt; k − 1 recurse on L with k, |L| &lt; k − 1 recurse on G with k − |L| − 1.

**A trace by hand.** n = 15 and A = 12, 3, 17, 8, 5 | 20, 1, 14, 9, 11 | 6, 19, 2, 15, 10 (the bars mark the three groups).

- sort each group: 3 5 **8** 12 17, then 1 9 **11** 14 20, then 2 6 **10** 15 19. The medians are 8, 11, 10.
- the median of [8, 11, 10] is 10, so p = 10.
- L = 3, 8, 5, 1, 9, 6, 2 has 7 elements. G = 12, 17, 20, 14, 11, 19, 15 has 7 elements.
- p happens to be the true median here. It does not have to be: the guarantee is only that neither side is bigger than 7n/10 = 10.5.

<Guide fig="median of medians" shows="The array cut into groups, one group per column, each column sorted with the biggest on top. A red ring marks each group's median. The yellow cell is the pivot p, the median of those medians. Blue cells are certainly at most p, red cells are certainly at least p, white cells could go either way.">
1. Each **column is one group**, sorted, biggest on top. The **red ring** is that group's median. Columns are lined up left to right by their median, so the yellow cell (p) sits in the middle column.
2. **Blue cells** are guaranteed to be ≤ p: everything below the ring in a column to the left, plus the ring itself. **Red cells** are guaranteed to be ≥ p. **White cells** could go either way. This picture is the proof of the lemma below.
3. Set the input to **sorted**, then **reversed**, then reshuffle. p changes and the true rank of p changes, but "worst side" never goes over the promised limit.
4. Switch to **groups of 3**. The guarantee weakens to 2n/3, and the next figure shows why that ruins the linear bound.
</Guide>

<Fold title="words for this lecture">

- **comparison model**: the only way an algorithm may learn about the items is by comparing two of them. Mergesort and quicksort are in it. It works for any ordered set.
- **outside the model**: with integers or strings you can also ask "is a = 5?" or "what is the third digit of a?". Counting sort and radix sort use this.
- **permutation** π of the input: the answer to "where does each element belong". For A = [23, 14, 2, 5, 76], π = (3, 2, 0, 1, 4) means A[0] is the 3rd smallest (counting from 0), A[1] the 2nd, and so on. Each input corresponds to exactly one permutation.
- **adaptive**: the next comparison can depend on the earlier answers.
- **decision tree**: a picture of one algorithm on inputs of size n. Each internal node is a comparison with two children (&lt; or &gt;). Each leaf is a finished answer.
- **depth** of the tree = the most comparisons the algorithm ever makes = its worst case.

</Fold>

### the lower bound

**Theorem (5.2.1).** Any comparison sort makes at least log(n!) = Θ(n log n) comparisons in the worst case.

<Steps title="proof of the lower bound">

<Step>

Sorting is exactly as hard as finding the hidden permutation π. (Tag each item with its starting position and then sorting gives π for free. Knowing π gives the sorted array for free.) So count answers instead of thinking about a particular algorithm.

</Step>

<Step>

There are n! possible permutations, and the algorithm may not stop while two of them are still consistent with what it has seen. So the decision tree needs at least n! leaves.

</Step>

<Step>

A binary tree of depth d has at most 2<sup>d</sup> leaves, so 2<sup>d</sup> ≥ n!, i.e. d ≥ log₂(n!).

</Step>

<Step>

log(n!) = Θ(n log n): n! ≤ n<sup>n</sup> gives at most n log n, and n! ≥ (n/2)<sup>n/2</sup> gives at least (n/2) log(n/2).

</Step>

</Steps>

<Recall q="State the sorting lower bound and its proof in three lines.">

Any comparison sort needs at least log₂(n!) = Θ(n log n) comparisons. Each of the n! orderings must reach a different leaf of the decision tree. A binary tree of depth d has at most 2<sup>d</sup> leaves, so d ≥ log₂(n!).

</Recall>

<Recall q="Suppose each question has 3 possible answers (&lt;, =, &gt;) instead of 2. How does the counting argument change?">

A decision tree of depth d now has at most 3<sup>d</sup> leaves instead of 2<sup>d</sup>. If there are A possible answers to tell apart, then 3<sup>d</sup> ≥ A, so d ≥ log₃ A. The recipe is the same: count the answers, count the outcomes per question, take the log.

</Recall>

<Recall q="Why is the bound about comparisons and not about time?">

The theorem lets the algorithm rearrange, move and copy items for free and counts only comparisons. Time is at least the number of comparisons, so the bound also holds for time, but the reverse is not claimed.

</Recall>

### outside the comparison model

<Spec
  name="counting sort"
  input="n integers, each one of k possible values (say 1 to k)"
  output="the n integers in sorted order, and equal values in their original order (stable)"
  note="time O(n + k). The k matters: with k much bigger than n you cannot just store the counts that are nonzero, because reading them back in order needs a priority queue, which costs Ω(log n) per operation."
/>

**Stable** means: if two items are equal and a comes before b in the input, then a comes before b in the output. This matters only when the items carry more than the key, and it is what radix sort needs.

Counting sort:

1. make an array count[1..k] of zeros, and add one for each input item's value (time O(n + k))
2. a prefix sum turns counts into ends: prefix[v] = where the block of v's ends in the output
3. scan the input <U>right to left</U>: put each item at slot prefix[v] − 1 and decrease prefix[v]. Scanning right to left keeps equal items in order (the lecture keeps a linked list per value and appends, which is the same idea).

<Guide fig="counting sort" shows="Counting sort placing one item per press. Each item is its key plus a letter (1a, 1b) that says which copy it is. Under each key are its count and its prefix: where that key’s block ends in the output.">

2. Read the "count" and "prefix" labels under each key: prefix is where that key's block ends.
3. Press **finish**, then switch **scan** to left to right. The output is still sorted by key, but items with equal keys (same number, different letters) come out reversed. That is what **not stable** looks like.
</Guide>

**Least-significant digit first (LSD):** sort the whole array by the last digit, then by the next-to-last digit, and so on to the first digit. Each pass uses a <Hl>stable</Hl> sort (counting sort).

Example from lecture: 353 457 657 839 436 720 355. After the last digit: 720 353 355 436 457 657 839. After the middle digit: 720 436 839 353 355 457 657. After the first digit: 353 355 436 457 657 720 839.

**Why it works (Theorem 5.3.1):** by induction, after pass i the array is sorted by its last i digits. Pass i+1 puts items with different (i+1)th digits in the right order. Items with the same (i+1)th digit stay in their earlier order because the sort is stable, and that earlier order is already correct by the hypothesis.

2. Switch **inner sort** to "scrambles ties". Then press **break it: 123 112**. The final answer is wrong: ties in the last digit were sorted by the wrong order.
3. Switch **direction** to "most digit first": this is the bucket version from lecture. It works but needs to remember all buckets. LSD does not.
</Guide>

<Recall q="Why must radix sort's inner sort be stable?">

After pass i the array is sorted by the last i digits. On pass i+1, items tied in that digit must keep the order they already had, because that order is the correct order of their last i digits. <Fold title="words for this lecture">

- **dictionary data structure**: a structure supporting insert, lookup and (often) delete. The notes ignore the object and only track the keys.
- **binary search tree (BST)**: a binary tree where each node stores a key, everything in its left subtree is smaller and everything in its right subtree is larger. Lookup walks down from the root, going left or right.

**The idea:** perfect balance is too expensive to maintain, so allow slack. The pivot in lecture 4 was allowed to be "near" the middle. The B-tree keeps all leaves at one depth and gets its slack from nodes of different sizes.

### B-trees

A **B-tree** for a chosen t ≥ 2 has three properties:

1. Every node has between t − 1 and 2t − 1 keys, except the root, which has between 1 and 2t − 1. The keys in a node are a sorted array.
2. A non-leaf with j keys has j + 1 children. The subtree under child i holds keys between the (i−1)th and ith key of the parent.
3. <Hl>All leaves are at the same depth.</Hl>

- **lookup:** binary search in the node. Either the key is there, or you learn which child to descend into.
- **insert:** walk down as if for lookup. If you meet a **full** node (2t − 1 keys), split it before going on. At the leaf, put the key into the node.
- **split:** the median key goes up into the parent, and the other 2t − 2 keys become two nodes of t − 1 keys each, hung on the left and right of the median. If the root splits, a new root is created holding only the median. That is the only way the tree gets taller: <U>it grows at the top, so all leaves stay at the same depth</U>.

<Check q="In a B-tree with t = 3, how many keys can a node other than the root hold?" options={["between 2 and 5", "between 3 and 6", "between 1 and 3", "between 3 and 5"]} why="t − 1 = 2 at least and 2t − 1 = 5 at most. A node with 5 keys is full and is split before an insert passes through it." />

**Trace, t = 3** (max 5 keys per node). Start with root H M R and leaves [A B C D], [K L], [N O], [T Y Z].
- insert E: it goes to the leftmost leaf, making it [A B C D E], which is now full.
- insert F: on the way down we meet that full leaf and split it. C moves up to the root, which becomes C H M R, and the leaf becomes [A B] and [D E F].
- a later insert that meets a full root splits the root first: the median becomes a new one-key root and the tree is one level taller.

<BTreeLab />

**Why insert keeps the three properties (Theorem 6.3.1):**
- <U>Leaf depth</U>: the tree only gets taller by splitting the root, which lifts every leaf by one at once.
- <U>Key counts</U>: a split leaves two nodes of exactly t − 1 keys. The parent gains one key, but it was not full, or we would have split it first. The leaf we finally insert into was not full either.
- <U>Order</U>: a split keeps the "between two keys" property, and the new key goes in a leaf.

**Cost.**
- depth is O(log<sub>t</sub> n) since every internal node has at least t children (except possibly the root)
- lookup: log<sub>t</sub> n levels × O(log t) per binary search = (log n / log t) · log t = <O>O(log n)</O>. The t cancels.
- insert: lookup plus up to one split per level, each O(t), plus O(t) to insert into the leaf: <O>O(t log n)</O>
- large t is for disks: one node is one disk read. With 10<sup>9</sup> keys and t = 1000, the top two levels fit in memory and only the bottom needs a read. Small t (t = 2, the 2-3-4 tree) is for memory, and it is the one that becomes red-black trees.

<Check q="What is the only thing that makes a B-tree one level taller?" options={["splitting the root", "any split", "inserting into a full leaf", "every 2t − 1 inserts"]} why="A root split creates a new root above everything, which pushes every leaf down by one at the same time. That is why all leaves stay at the same depth." />

<Recall q="State the three B-tree properties.">

(1) Every non-root node has t − 1 to 2t − 1 keys, and the root has 1 to 2t − 1. (2) A non-leaf with j keys has j + 1 children, and child i holds keys between key i − 1 and key i. (3) All leaves are at the same depth.

</Recall>

<Recall q="Why can a split never make the parent over-full?">

We split full nodes on the way down, so when we split a child, its parent was already checked and is not full. The parent gains one key and is at most full, never over-full.

</Recall>

<Recall q="Why is B-tree lookup O(log n) and not O(t log n)?">

Depth is log<sub>t</sub> n = log n / log t, and each level costs log t for binary search. The product is log n. The t cancels.

</Recall>

### red-black trees

A binary tree is easier to code and usually faster for in-memory work, and the red-black tree is the standard balanced one (Linux kernel, Java HashMap). The lecture's view: a red-black tree is a 2-3-4 tree drawn as a binary tree. Missing children are NULL, and keys are only at internal nodes.

- a 2-3-4 node with **1 key** is one black node
- a node with **2 keys**: a black node with one red child, on the left or the right (it is not one-to-one; a 3-node can lean either way)
- a node with **3 keys**: a black node with two red children (a red left child and a red right child)
- a **red link** is "stuck to my parent": it is inside one 2-3-4 node. A **black link** is an edge of the original 2-3-4 tree.

Two properties follow from the 2-3-4 tree rules:

1. no two red links in a row (a red link is always followed by a black one)
2. for every node, all paths down to NULL have the <U>same number of black links</U> (the black-depth)

Together: the longest root-to-leaf path has at most twice as many links as the shortest, so height ≤ 2 log(n + 1) (CLRS Lemma 13.1). Lookups are O(log n).

**Insert.** Insert like a normal BST with a new **red** link, as if adding a key to a bottom 2-3-4 node. Then fix what that broke:
- a 4-node that must split (a black node with two red children): <O>swap colors</O> (the children become black, the parent red and it pushes up into its own parent's node). This is the "uncle is red" case in the book.
- other cases break a property, so use a **rotation**: a local change that lets a child take its parent's place while keeping the left-to-right order (subtrees A, B, C keep their order). One rotation or two (a double rotation) puts the node back in the right shape. This is the "uncle is black" case.

The lecture splits full nodes on the way down (like a B-tree); the book, and the figure, insert first and repair on the way back up. Both keep the same correspondence with the 2-3-4 tree.

<Lecture n={7} title="amortized analysis" tldr="One operation can be expensive while the average over any sequence stays small. Prove it with a bank or a potential Φ.">

<Spec
  name="amortized cost of a sequence"
  input="a data structure and a sequence of n operations on it (the worst possible sequence)"
  output="total cost of the n operations divided by n"
  note="there is no probability involved. 'Average' here means average over the operations of one worst-case sequence."
/>

<Fold title="words for this lecture">

- **amortized cost** (Definition 7.1.1): the total cost of a sequence of n operations divided by n.
- **amortized complexity** (7.1.2): if <U>every</U> sequence of n operations costs at most f(n) in total, the amortized cost per operation is at most f(n)/n.
- **worst case vs amortized:** one operation can be very expensive and the amortized cost still small. With 100 operations of cost 1 and one of cost 100, the worst case is 100 but the average is 200/101 ≈ 2.
- **bank L** (piggy bank): cheap operations deposit extra tokens, expensive ones withdraw. Start with L₀ = 0.
- **amortized cost of operation i**: c′ᵢ = cᵢ + Lᵢ − Lᵢ₋₁ (its true cost plus the change in the bank).
- **potential Φ**: the same thing as a bank, but computed as a function of the current state instead of tracked by deposits. c′ᵢ = cᵢ + Φᵢ − Φᵢ₋₁.
- **link to the total:** Σ cᵢ = Σ c′ᵢ + L₀ − Lₙ. If L₀ = 0 and Lₙ ≥ 0, then <Hl>total true cost ≤ total amortized cost</Hl>. That is why the bank must never go negative.

</Fold>

One increment can flip log n bits (1111 → 10000), so the worst case is Θ(log n). Amortized it is 2. Four ways to see it, all equivalent:

1. **per-bit bank:** every time a bit flips 0 → 1, put a token on it. A flip 1 → 0 is paid for by that token. An increment flips exactly one bit to 1, so it is charged 1 for the flip plus 1 for the token: 2.
2. **one global bank:** same, summed over the bits.
3. **potential:** Φ = the number of 1s in the counter. Φ₀ = 0, Φ ≥ 0, and c′ = c + ΔΦ = 2.
4. **directly:** bit i flips every 2<sup>i</sup> steps, so n increments flip it n/2<sup>i</sup> times, in total Σ n/2<sup>i</sup> ≤ 2n.

<Fold title="words for this lecture">

### version 1: lists (with sizes)

Each set is a linked list. Every element points to the head (the representative), and the head stores the size. Find is O(1). Union(x, y): splice the **shorter** list into the longer one and update the head pointers of every element of the shorter list. That is O(min(|S|, |T|)) for a Union.

**Theorem 9.2.1:** the total time is O(m + n log n). Proof: charge each Union's cost to the elements of the smaller set, one each. Whenever an element e is charged, it was in the smaller set, so the set containing it at least <Hl>doubles</Hl>. It can double at most log n times, so each element is charged at most log n times, and the total is at most n log n. It is tight: n/2 unions of pairs, then n/4 of 4s, and so on cost Ω(n log n).

**Properties of rank** (easy inductions):
1. a non-root has rank strictly less than its parent's
2. when path compression changes x's parent, the new parent has strictly larger rank than the old one
3. only roots change rank, and a non-root never becomes a root again
4. when a node first reaches rank r, its tree has at least 2<sup>r</sup> nodes (two rank-(r−1) trees merged)

**Lemma 9.3.1:** at most n/2<sup>r</sup> nodes have rank ≥ r. Each such node had ≥ 2<sup>r</sup> nodes in its tree when it got that rank, and those sets are disjoint for different nodes, so there are at most n/2<sup>r</sup> of them. In particular the height is at most log n.

**Theorem 9.3.2:** with union by rank and path compression, the total time is <O>O(m log\* n)</O>.

<Steps title="idea of the proof">

<Step>

Count the parent pointers that all the Finds follow.

</Step>

<Step>

Following a pointer that goes straight to a root costs O(1) per Find. Set those aside.

</Step>

<Step>

Put the nodes into buckets by rank: bucket i holds the ranks from a tower of i − 1 twos up to a tower of i twos minus 1. There are only O(log\* n) buckets.

</Step>

<Step>

A Find path can cross from one bucket into a higher one at most log\* n times. Charge those steps to the Find: O(log\* n) each.

</Step>

<Step>

The other steps stay inside one bucket. Charge each to the node being left. Each time, path compression gives that node a parent of strictly larger rank, so a node in bucket i can be charged at most (a tower of i twos) times before its parent is in a higher bucket.

</Step>

<Step>

Bucket i has at most n divided by (a tower of i twos) nodes, by Lemma 9.3.1. So each bucket is charged at most n in total, and all buckets together O(n log\* n).

</Step>

<Lecture n={10} title="universal and perfect hashing" tldr="Every fixed hash function has a bad set of keys. Draw the function at random from a universal family and a lookup is O(1) in expectation. For a fixed set of keys, two levels give O(1) in the worst case.">

<Spec
  name="dictionary by hashing"
  input="a huge universe U of possible keys, a small set S ⊆ U of N keys that are actually stored, and a table A with M slots"
  output="Lookup(x) says whether x is stored. Insert(x) and Delete(x) change S"
  note="a hash function h sends every key of U to a slot, and key x lives in A[h(x)]. We want three things: few collisions, M = O(N), and an h that is fast to compute. Lecture 6 did this in O(log n) with trees. The goal here is O(1)."

<Fold title="words for this lecture">

- **universe U**: every key that could ever show up, for example all strings of at most 40 characters. Assuming keys come from a known U is stronger than the comparison model, and weaker than radix sort's assumptions.
- **S** and **N**: the set of keys actually stored, and its size N = |S|.
- **hash table** A of size **M**, and a **hash function** h: U → [M], where [M] means the slots 1 to M.
- **collision**: two different keys x ≠ y with h(x) = h(y).
- **separate chaining**: A[i] is a linked list of every stored key that hashes to i.
- **universal**: a probability distribution over hash functions in which every pair x ≠ y collides with probability at most 1/M.
- **universal hash family**: a set of functions whose uniform distribution is universal. "H" is used for both the set and the distribution.
- **perfect** for S: every lookup takes O(1) time in the worst case.
- **indicator variable** C<sub>xy</sub>: 1 if x and y collide, 0 if not. Its expectation is the probability of a collision.
- **linearity of expectation**: the expectation of a sum is the sum of the expectations, even when the terms depend on each other.
- **Markov's inequality**: for X ≥ 0, Pr[X ≥ a] ≤ E[X]/a.

</Fold>

### the operations, with chaining

- **Lookup(x):** walk the list at A[h(x)] until you find x or reach the end.
- **Insert(x):** put x at the front of the list at A[h(x)]. Always O(1).
- **Delete(x):** walk the list at A[h(x)], remove x.

Lookup and delete cost O(length of the list at A[h(x)]). So the whole question is how many keys collide.

### bad news: every fixed h has a bad set

**Theorem 10.2.1.** For any hash function h, if |U| ≥ (N − 1)M + 1, then there is a set S of N keys that all hash to the same slot.

<Steps title="proof (pigeonhole, by contrapositive)">

<Step>

Contrapositive: if every slot receives fewer than N keys of U, then |U| ≤ (N − 1)M.

</Step>

<Step>

Each of the M slots receives at most N − 1 keys of U.

</Step>

<Step>

Every key of U goes to some slot, so |U| ≤ (N − 1)·M ✓.

</Step>

<Step>

So when U is that big, some slot receives at least N keys. An adversary who knows h picks those N keys as S, and every lookup walks a list of length N.

</Step>

</Steps>

### the fix: choose h at random

This is randomized quicksort again. For any fixed pivot rule there is a bad array, but for every array a random pivot is good in expectation. Here: for any fixed h there is a bad S, but <Hl>for every S, a randomly chosen h is good in expectation</Hl>. Once chosen, h stays the same, or lookups would not find anything.

- **First idea, a fully random function:** for each x in U pick h(x) uniformly at random. It has the right property, but it has no structure, so the only way to remember it is a table with one entry for every key of U. That is the dictionary problem we started with.
- **What we want:** the useful property of a random function, in a function that is small to store and fast to compute.

### universal hashing

**Definition 10.3.1.** A probability distribution H over hash functions U → [M] is **universal** if for all x ≠ y in U, Pr[h(x) = h(y)] ≤ 1/M when h is drawn from H.

A fully random function has this property. The point is that much smaller families have it too.

**Theorem 10.3.2.** If H is universal, then for every set S of N keys and every x in U, the expected number of collisions between x and the keys of S is at most <O>N/M</O>.

<Steps title="proof (indicators and linearity of expectation)">

<Step>

For each y in S with y ≠ x, let C<sub>xy</sub> = 1 if h(x) = h(y), and 0 otherwise.

</Step>

<Step>

E[C<sub>xy</sub>] = Pr[h(x) = h(y)] ≤ 1/M. That is the definition of universal.

</Step>

<Step>

The number of collisions with x is the sum of C<sub>xy</sub> over those y.

</Step>

<Step>

By linearity of expectation, E[sum] = sum of E[C<sub>xy</sub>] ≤ (at most N terms) · 1/M = N/M ✓.

</Step>

</Steps>

### building one: the matrix method

- Keys are u bits long. The table size is M = 2<sup>b</sup>, so a slot number is b bits long.
- h is a random b × u matrix of 0s and 1s ("short and fat"). Define h(x) = h·x, with all arithmetic mod 2.
- In plain words: <Hl>h(x) is the XOR of the columns of h in the positions where x has a 1.</Hl>
- Storing h takes b·u bits, which is tiny next to a table over all of U.

The lecture's example: the columns of h are (1,0,1), (0,1,1), (0,1,1), (0,1,0) and x = 1010. x picks columns 1 and 3, and (1,0,1) + (0,1,1) = (1,1,0) mod 2.

**Theorem 10.3.5.** For all x ≠ y, Pr[h(x) = h(y)] = 1/M exactly. So this family is universal.

<Steps title="proof (leave one column for last)">

<Step>

x ≠ y, so they differ in some bit i. Say x has a 0 there and y has a 1.

</Step>

<Step>

Draw every column of h except column i.

</Step>

<Step>

h(x) is already decided. x has a 0 in position i, so column i is never added into it.

</Step>

<Step>

h(y) is not decided, because it includes column i. Each of the 2<sup>b</sup> possible columns gives a different value of h(y).

</Step>

<Step>

Exactly one of those 2<sup>b</sup> values equals h(x). So Pr[h(y) = h(x)] = 1/2<sup>b</sup> = 1/M ✓.

</Step>

</Steps>

### perfect hashing

Now S is fixed and known in advance, and there are only lookups, like a printed dictionary. Build time does not matter much. A sorted array or a balanced tree gives O(log N) per lookup. The goal is <Hl>O(1) in the worst case</Hl>, not only in expectation. A hash function is **perfect** for S if every lookup takes O(1) time.

**Method 1: space N².** Use a table of size M = N². Draw h from a universal family, hash all of S and check for collisions. If there are any, draw again.

**Theorem 10.4.1.** If H is universal with M = N², then Pr[no collisions in S] ≥ 1/2.

<Steps title="proof (count the pairs)">

<Step>

S has C(N, 2) = N(N − 1)/2 pairs of different keys.

</Step>

<Step>

Each pair collides with probability at most 1/M = 1/N².

</Step>

<Step>

Pr[some pair collides] ≤ the sum over all pairs = N(N − 1)/(2N²) ≤ 1/2.

</Step>

<Step>

So each draw is perfect with probability at least 1/2, and you expect at most 2 draws.

</Step>

</Steps>

**Method 2: space O(N), with two levels.**

1. Draw a first-level h from a universal family into a table of size N. There will be collisions.
2. Let n<sub>i</sub> be the number of keys of S that land in bin i.
3. For each bin i, use method 1 on just its n<sub>i</sub> keys: a second-level table A<sub>i</sub> of size n<sub>i</sub>², with its own function h<sub>i</sub> that is perfect for those keys.
4. **Lookup(x):** compute i = h(x), then look in A<sub>i</sub>[h<sub>i</sub>(x)]. That is O(1) in the worst case (Theorem 10.4.2).

The space is N for the first table plus Σ n<sub>i</sub>² for the second-level tables. So we need Σ n<sub>i</sub>² = O(N).

**Theorem 10.4.3.** If H is universal onto a table of size N, then Pr[Σ n<sub>i</sub>² &gt; 4N] &lt; 1/2.

<Steps title="proof (count ordered pairs)">

<Step>

The trick: n<sub>i</sub>² is the number of <U>ordered</U> pairs (x, y) of keys in bin i, counting (x, x) too. A bin holding a, b, c has 9 such pairs.

</Step>

<Step>

So Σ n<sub>i</sub>² = the sum of C<sub>xy</sub> over all x and y in S, where now x is allowed to equal y.

</Step>

<Step>

The N pairs (x, x) always collide. They contribute exactly N.

</Step>

<Step>

The N(N − 1) ordered pairs with x ≠ y each have E[C<sub>xy</sub>] ≤ 1/M = 1/N. They contribute at most N − 1.

</Step>

<Step>

So E[Σ n<sub>i</sub>²] ≤ N + (N − 1) &lt; 2N.

</Step>

<Step>

Markov's inequality: Pr[Σ n<sub>i</sub>² &gt; 4N] &lt; 2N/4N = 1/2. So redraw the first-level h until Σ n<sub>i</sub>² ≤ 4N. You expect at most 2 draws.

</Step>

</Steps>

<Recall q="Define a universal hash family.">

A set H of functions U → [M] such that, for h drawn uniformly from H, every pair of distinct keys x ≠ y has Pr[h(x) = h(y)] ≤ 1/M.

<Recall q="State and prove the bound on the expected number of collisions for a lookup.">

If H is universal, the expected number of keys of S that collide with x is at most N/M. Proof: let C<sub>xy</sub> indicate h(x) = h(y). E[C<sub>xy</sub>] ≤ 1/M by universality. The number of collisions is the sum over y in S, y ≠ x, and by linearity its expectation is at most N · 1/M.

<Recall q="Why does a random function beat an adversary when a fixed one does not?">

By the pigeonhole theorem, an adversary that knows a fixed h can find N keys that all collide. If h is drawn at random after the keys are fixed, each pair collides with probability at most 1/M, so the expected number of collisions is small whatever the keys are.

They differ in some bit i, where say x has 0 and y has 1. Fix all columns but column i. Then h(x) is fixed, and the 2<sup>b</sup> choices of column i give 2<sup>b</sup> different values of h(y), exactly one of which equals h(x).

</Recall>

<Recall q="In two-level perfect hashing, why is the total space O(N)?">

Σ n<sub>i</sub>² counts ordered colliding pairs including each key with itself: N + (ordered pairs of different keys that collide). In expectation that is at most N + N(N − 1)/N &lt; 2N. By Markov it exceeds 4N with probability below 1/2, so redraw until it does not.

<Recall q="HW1.3 (group sorting): k-group-sort an array in O(n log k) worst-case time, and prove it.">

**A k-group-sorted array** has k consecutive groups of n/k elements, every element of a group larger than all elements of earlier groups.

**Algorithm** GroupSort(A, k): if k = 1, return A (any array is 1-group-sorted). Otherwise find the median of A with BFPRT, partition A around it into L (the n/2 smaller elements) and G (the n/2 larger elements), then return GroupSort(L, k/2) followed by GroupSort(G, k/2).

**Correctness** (induction on k). For k = 1 it is trivially true. For k &gt; 1: L and G each have n/2 elements, and every element of L is smaller than every element of G. By induction, GroupSort(L, k/2) is (k/2)-group-sorted, that is, it has k/2 groups of size (n/2)/(k/2) = n/k, and likewise for G. Put together, we get k groups of size n/k, and the groups from L are all smaller than the groups from G. So the output is k-group-sorted.

**Time.** The median and the partition cost cn (BFPRT is linear). So T(n, k) = 2T(n/2, k/2) + cn and T(n, 1) = O(1). The recursion has log k levels (k halves down to 1). Each level does total work cn, because the pieces at one level have sizes summing to n. So T = cn log k + O(k) = O(n log k) (the leaves number k ≤ n).

Figure: median quicksort, stopped after d = log k levels.

<Recall q="HW3.3 (k-th smallest of every growing prefix): for each i, b_i is the k-th smallest of a_1 … a_(k+i−1). Give an O(n log k) algorithm and prove it.">

**Algorithm.** Keep a **max-heap H of size exactly k** that will hold the k smallest elements seen so far.
1. Put a_1 … a_k in H (build-heap, O(k)). Output b_1 = the root of H (the largest of these k, i.e. the k-th smallest of the first k).
2. For j = k + 1 to n: if a_j &lt; root(H), replace the root by a_j and sink it (O(log k)); otherwise do nothing. Output b_(j−k+1) = root(H).

**Invariant:** after reading a_1 … a_j (j ≥ k), H contains exactly the k smallest elements of a_1 … a_j, so its root, the largest of them, is the k-th smallest of a_1 … a_j.

**Proof.** True for j = k. Suppose true for j and read x = a_(j+1). If x &gt; root: at least k elements (the ones in H) are smaller than x, so x is not among the k smallest and H is unchanged and still correct. If x &lt; root: then the old root now has k smaller elements (the other k − 1 in H, plus x), so it drops out of the k smallest, and the new k smallest are H minus its root plus x, which is exactly what the replace-and-sink produces. In both cases the invariant holds for j + 1, so each output is correct.

**Time.** O(k) to build, then n − k steps each with one comparison and at most one sink of O(log k) (the heap has k elements): O(k + (n − k) log k) = O(n log k).

Figure: the binary heap lab. The useful heap size is k, not the prefix length, because only the k smallest can ever matter for the k-th smallest.

</Recall>

**Recitation 1 warm-up** (selection from two sorted arrays): to find the kth smallest of two sorted arrays A and B of n elements each in O(log n) time, compare A[k/2] with B[k/2]. If A[k/2] ≤ B[k/2], the first k/2 elements of A are all smaller than the answer and can be discarded, and everything after B[k − k/2] can be discarded too. Recurse with k − k/2. The rank halves each time: T(k) = T(k/2) + O(1) = O(log k).
